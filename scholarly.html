1. Abstract

PoW - Pet Adoption on Web is a SPA-type web application, created to facilitate pet adoption process. The platform allows users to register, add pets and manage their resources, manage their adoption requests, all of this being available through a responsive interface. The application is built without any framework, using only HTML5, CSS3, JavaScript, PHP and SQLite for the database. The web application also allows media management, data export in CSV/JSON and RSS feeds, and also offers protection against XSS and SQL injection. This document describes the application interface design, architecture, data modeling and main features.

2. Introduction

This application was developed as part of a college project, with the aim of facilitating animal adoption through an easy-to-use platform. We used basic technologies (HTML, CSS, JavaScript, PHP, SQLite) and complied with all requirements. The application runs locally and does not use external services.

3. Interface Design and Justification

3.1 Design Choices

We chose a simple, clear and easy-to-read design to avoid visual overload and provide users with a friendly experience. The color palette used includes a main shade of green, symbolically associated with nature and animals, in contrast with a teal shade for highlighting. This contrast was chosen to visually differentiate the interface elements.

We opted for large visual components (e.g. buttons, cards, forms) and generous spaces between sections, to facilitate use on mobile devices. Each page of the application (e.g. add pets, requests, admin panel) is accessible from a menu positioned at the top of the interface, but which is not persistent when scrolling. However, that footer remains persistent when scrolling, to also provide the name of the logged-in user.

3.2 Responsiveness and Usability

We made sure that the application interface is responsive, automatically adapting to various screen sizes, including mobile phones. This was achieved by using CSS techniques such as media queries.

Navigation between pages is done without reloading the entire site (SPA), thus contributing to a fluid experience. Animations were avoided, preferring simple loading of content.

4. System Architecture

4.1 Overview

We structured the application as a SPA (Single Page Application) web system, where: the frontend is written in HTML, CSS and JavaScript, and the backend is made in PHP with storage in SQLite. The frontend dynamically loads the content into the page using fetch(), without reloading the entire site. The backend responds to requests received from the frontend, performs operations on the database and sends the results in JSON format. PHP sessions were also used for authentication and access control.

4.3 Technologies Involved

For data export we used CSV format, and JSON was used exclusively for communication between JavaScript and the backend. In addition, the application also allows importing animals via CSV files, directly from the Add Pets page. The adoption feed is generated via RSS, with a limit of 10 animals displayed at most. The application uses the fetch() method to make asynchronous calls to the backend.

4.4 Milestones

The project was developed in pieces, starting with certain important stages:

Project initialization - configuring the XAMPP environment, defining the directory structure and the SQLite database (e.g. several tables were added along the way, and some modified, initially we started with the table that has user management).

Authentication and sessions - implementing login/register functionalities and maintaining user sessions.

Animal management - developing pages for adding, editing and deleting animals, including media, then navigating adoptions.

Adoption requests and notifications - creating a mechanism for requesting and sending notifications.

Additional functionalities - CSV/JSON export, CSV import, RSS feed, HTML/CSS validation and XSS/SQL injection protection by checking all user inputs.

Architectural diagram & documentation - creating documentation related to the project.

5. Data Structure and Sources

5.1 Database Schema

The database consists of 7 tables and covers the functionality of the application. The tables include users, animals, media, requests, notifications, feeding_calendar and medical_history. Also, some tables are linked by relevant foreign keys (e.g. an animal is associated with a user by owner_id).

All data in the tables is provided by users through the application, where insertion is done through forms. Media resources (images, audio, video) can come from various free license sites such as Pexels or Pixabay or from a personal archive.

5.2 Media and Data Origins

Media resources (images, videos, audio files) can be optionally uploaded by users while filling out the animal add form. These resources are saved locally in a folder called uploads and are associated in the database via a unique identifier (e.g. the path to the uploads file).

6. Application Features

6.1 Register/Login

We allow new users to register by filling out a form with a username, email address, and password. The frontend performs validation before submission. After successful registration, the user is redirected to the login page. If authentication is successful, they are directed to the dashboard (e.g. home page), and their session remains active until they log out. If there are problems, such as duplicate emails, an error message is displayed.

6.2 Add & Manage Pets

Once authenticated, users can submit pets for adoption using a dedicated form, where they fill in details such as name, breed, pick-up address and optionally upload images, videos or audio files. We also support importing via CSV files.

Pets added by the user appear in the “My Pets” section. From there, they can edit descriptions, manage feeding schedules and medical history, update media files and permanently delete pets.

6.3 Browse & Request

In the Browse Pets section, we display all pets available for adoption except those owned by the logged-in user. Each pet is shown as a card with its basic details. Clicking the card opens a full details page. From there, a user can submit an adoption request and the pet owner sees all requests and can choose to approve or reject them.

6.4 Admin Panel

The administrator has access to an additional page called panel where he can run the database initialization script, delete a pet from the database based on its ID, and export all registered animals to a csv file.
